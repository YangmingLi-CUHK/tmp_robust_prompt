4.为什么“非LCC”不是全部根因

4.1可计算的clean上界

best test accuracy=0.3862对应约930/2408个正确节点。LCC外test节点只有197个。未知逐节点预测时，删去LCC外节点后的同一分类器accuracy必在：

lower=(930−197)/2211=0.3315
upper=930/2211=0.4206

因此，仅改变test组成最多把0.3862推到约0.4206，不可能直接恢复到历史Cora-pretrain的0.6262。LCC错误会改变攻击过程和后续message passing，仍须修复；但不能拿它解释全部clean差距。

4.2真正支配解释的是坐标系错配

Citeseer: XCite∈R2110×3703
PyG SVD: X′Cite=UCite[:,1:1433]ΣCite[1:1433]∈R2110×1433
pretrain first layer: HCite=ÂCiteX′CiteW0

downstream: XCora∈R2708×1433（原始BoW词列）
current transfer: HCora=ÂCoraXCoraW0

X′Cite[:,j]是Citeseer内部第j个主成分得分，XCora[:,j]是Cora词表第j个词项；两者没有共同坐标语义。第一层权重W0虽然shape可加载，但每一行被解释成了不同变量。这不是常规domain shift，而是basis mismatch。

审计判断：该实验可以保留为“shape-compatible stress test”，不能把结果解释成有效的Citeseer知识迁移。脚本第21行已经诚实写明这一边界。当前135项test均值0.2992接近多数类0.3040，与错基底预期一致。

5.最小而正确的修复路线

原则：不覆盖现有full-Cora数据与历史结果。新建并行的paper_lcc数据根，先做低成本clean gate，再决定是否重跑六浓度。Citeseer的135个checkpoint暂不重训，除非服务器cache身份检查失败。

阶段A：先关闭认知漏洞

  1. 把当前结果固定命名为full-Cora／shape-only／test-oracle exploratory。
  2. 停止引用reference/data.md:29-30的“2708=LCC”结论；后续文档使用2485/5069。
  3. 服务器记录citeseer.npz、SVD1433 cache和最早checkpoint的SHA256/mtime；若cache来源无法确认，先旁路备份并重算cache做tensor对比。

阶段B：建立paper-LCC并行数据

  1. 从当前clean Cora确定唯一2485节点LCC，保存旧→新node map；断言5069条无向非自环边、1433特征、7类、1个连通分量。
  2. 在重编号后的2485节点上重新生成平衡5-shot split；不能继承裁剪后的33-shot。
  3. 以同一个LCC、同一个split和floor(ptb×5069)预算重生成0.00/0.05/0.10/0.15/0.20/0.25。
  4. 新数据根与现有cache完全隔离；所有6档断言节点顺序、features、labels和split一致，翻转数与预算一致。

阶段C：两道gate

Gate操作继续条件失败时结论
Gate1：clean transfer在paper-LCC clean图上重跑135项或至少当前best＋val-best组；补Macro-F1/confusion matrix明显高于多数类且seed稳定停止六档；shape-only transfer无效
Gate2：robustness只在通过Gate1的checkpoint上跑6浓度×5 prompt seeds报告accuracy mean±std，并附Macro-F1可将崩塌归于图/prompt而非弱backbone

Checkpoint选择的最小修正

  • 按5个pretrain seed的validation accuracy mean选择augmentation/ratio组。
  • test只用于最终组的一次报告；不再用test排列135项。
  • 如果本轮仍只取单checkpoint，当前seed4恰好也是validation最高，可继续作探索用；正式结论仍应报告5-seed组统计。
  • 保留accuracy作为论文主metric，同时补Macro-F1与confusion matrix，防止多数类坍缩被0.3040 baseline掩盖。

必须加入的preflight

  • clean graph：N=2485,E=5069,F=1433,C=7,components=1
  • train：35个且每类5个；train/val/test互斥
  • 6档共享node map、features、labels、split
  • 每档symmetric difference精确等于目标预算
  • processed cache路径包含数据协议标识，禁止full/LCC共用
  • 日志首部打印数据协议、图统计、split统计、checkpoint选择来源

最终建议：不要立刻拿当前best跑一整套并宣称论文复现。先用并行paper-LCC完成Gate1；若仍在0.3–0.4附近，诚实终止这条shape-only迁移路线。若只是想看full-Cora探索曲线，当前seed4 checkpoint可以继续，但报告标题和结论必须明确协议边界。

独立复算方法

直接打开Torch ZIP序列化文件，读取/data/0的little-endian int64 storage，按[2,13264]还原COO indices；去除2708个自环并把双向entries规范化为唯一无向边集合。

对2708节点分别使用Union-Find与BFS复算连通分量；两者均得到78个分量、LCC=2485节点/5069边。各污染档与clean集合做add/delete/symmetric-difference。

split直接读取Torch ZIP storage与raw NPY；验证唯一性、两两交集、全集覆盖、类别计数和LCC归属。

附件使用正则完整解析135/135项；网格为3×3 augmentation pair×3 ratio×5 seed，无FAILED。

外部实现依据

DeepRobust Dataset文档：setting="nettack"使用largest connected component；setting="gcn"才使用full graph。

DeepRobust Dataset源码：require_lcc=True后调用largest_connected_components裁adj/features/labels。

PyG SVDFeatureReduction源码：只执行data.x=U[:,:k]@diag(S[:k])，不修改拓扑。
