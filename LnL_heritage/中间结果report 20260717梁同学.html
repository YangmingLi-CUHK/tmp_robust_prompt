执行摘要

主结论：NaN 已被高概率复现并定位到 similarity prompt 的反向传播。29 次异常中，forward tensor、CE/MSE/KL、total loss 和参数在更新前均有限；只有 sim 参数组的 57,340 个梯度在 loss.backward() 后同时变为 NaN。
  1. 相同 seed 仍随机分叉：完全相同的 seed=2 配置重复 20 次，9 次异常，首次异常分布于 epoch 120–237。
  2. 攻击不是必要条件：干净图 ptb=0.0 也触发 NaN。
  3. tau 不是必要条件：no_tau 仍在 epoch 131 触发；tau=0.4 也在 epoch 98 触发。
  4. 其他 filter 不是最初污染源：多 filter 异常中 degree、NSP、FC、other 和 answering 在裁剪前均有限，只有 sim 全量 NaN。
  5. 高度可信根因：prompt 融合使用 torch.all(... != 0) 判断有效行，并在 torch.where 内提前执行可能除零的表达式；这能完整解释“forward 有限、backward NaN”。

高度可信的根因

当前 prompt 融合代码：

wo_padding_mask = torch.all(g_mutiftpt_record != padding, dim=-1, keepdim=True)
node_prompt_len = wo_padding_mask.sum(1)

g_mutiftpt_final_output = torch.where(
    node_prompt_len != 0,
    g_mutiftpt_record.sum(1) / node_prompt_len,
    padding
)

问题 1：有效行判断

torch.all(row != 0) 要求 1433 个维度全部非零。一个合法 prompt 只要一个维度恰好为 0，就会被误判为 padding。语义上至少应当使用 any，更稳妥的是直接使用节点–prompt 分配 mask。

问题 2：where 不阻止除零

torch.where 的两个输入表达式都会先计算。即使 forward 最终选择 padding，除零分支的 backward 仍可能形成 0 × inf = NaN。

证据强度：29 次异常全部满足同一特征，且多 filter 实验中始终只有 sim 首先 NaN；no-tau、clean 图、MSE-only 也会触发。尚缺的最后直接证据是异常当步的 node_prompt_len==0 节点计数。

最终验证

最终判断：NaN 的直接发生点已经确定为 similarity prompt backward。现有全部实验最支持 prompt 融合处错误的 padding 判断与隐藏除零；攻击、tau、KL 和其他 filter 均不是必要原因。
