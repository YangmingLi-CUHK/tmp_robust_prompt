一、项目背景
================================================================================

项目目标：构建鲁棒的图提示学习（Robust Graph Prompt Learning）。在 GNN 预训练 +
Prompt Learning 的范式下，使下游节点分类任务在面对图结构扰动（如 Metattack 边污染）
时仍保持稳定且可接受的分类性能。

预训练配置：标准 GraphCL，GCN backbone，Cora 数据集
  aug1=dropN  aug2=permE  ratio=0.3  lr=0.01  epochs=200  hid_dim=256  num_layer=2

核心矛盾（修复前）：

  | Prompt 方法      | Clean Accuracy        | Attacked (Meta_Self-0.05) | 稳定性     |
  |------------------|-----------------------|---------------------------|------------|
  | GPPT (baseline)  | 57.1%                 | 27.9%                     | 跨seed稳定  |
  | RobustPrompt-T   | 27.6% (0.07~0.51)     | 11.4% (0.06~0.14)         | 极不稳定    |

GPPT 验证了数据管线、预训练权重和代码实现正确。但 RobustPrompt-T（即论文中的
GPromptShield）表现既差又不稳定，与论文 ICLR 2025 报告的水平严重不符。

3.1 prompt_graph/prompt/RobustPrompt_T.py — 核心修复（+56/-33 行）

3.1.1 实现 out_detect_pt 防御 prompt（原 line 231-232 直接 pass）

  原代码：out_detect_pt 分支为空，仅保留接口占位。

  修复后：基于边两端节点特征的 cosine similarity 识别 OOD 边（低相似度 = 可疑对抗边），
  OOD 边两端节点标记为需要 out_detect_pt，支持 p_plus 和非 p_plus 两种模式。

  具体逻辑：
    - 对每条边计算端节点特征归一化后的 cosine similarity: e = x_norm[src] · x_norm[dst]
    - 以 pt_dict['out_detect_pt'] = 0.5 为阈值，cosine ≤ 0.5 的边标记为 OOD 边
    - OOD 边两端节点去重后得到 node_use_ood_pt
    - p_plus 模式：用 out_detect_pt_a (Linear) + out_detect_pt_list (20 token bank)
      为每个受影响节点学习加权组合
    - 非 p_plus 模式：所有受影响节点共享同一个 prompt_out_detect_pt

3.1.2 修复 Attention 融合机制（原 line 277-282）

  原代码 Bug：
    g_mutiftpt_output, attn = self.attention_layer(...)
    g_mutiftpt_output = normalize(g_mutiftpt_record, p=1, dim=2)  ← 直接覆写！
    g_mutiftpt_final_output = g_mutiftpt_output[:,0,:]

    attention 输出在下一行即被 normalize(INPUT) 覆盖，attention 权重完全无效。
    同时 key_padding_mask 构造有误（keepdim + squeeze 导致维度错误），
    node filter 逻辑错误（用 == len(self.pt_keys) 而非检查全部为 padding）。

  修复后：
    g_mutiftpt_record = g_mutiftpt_record.reshape(N, K, D)  # K=prompt类型数
    g_mutiftpt_record = torch.cat([readout_token.expand(N,1,D), g_mutiftpt_record], dim=1)
    key_padding_mask = torch.all(g_mutiftpt_record == padding, dim=-1)  # (N, K+1)

    g_mutiftpt_output, attn = self.attention_layer(
        g_mutiftpt_record, g_mutiftpt_record, g_mutiftpt_record,
        key_padding_mask=key_padding_mask
    )
    g_mutiftpt_final_output = g_mutiftpt_output[:, 0, :]  # readout token 输出

    # 没有任何防御prompt的节点 → 输出归零，仅保留原始特征 x
    node_num_pt = (~key_padding_mask[:, 1:]).sum(-1)
    node_use_no_pt_indices = torch.nonzero(node_num_pt == 0).squeeze(-1)
    g_mutiftpt_final_output[node_use_no_pt_indices] = padding

  设计原理（对齐论文 Section 4.2 Self-Attention 融合策略）：
    - 在 K 个 prompt slot 前插入一个可学习的 readout_token
    - MultiheadAttention(query=key=value=所有slot) 让 readout token 通过 attention
      自适应地聚合各 slot 的信息
    - key_padding_mask 为 True 的位置被 attention 忽略（即空 slot 不参与聚合）
    - 输出取 readout token 位置 ([:,0,:])，作为该节点融合后的最终 prompt

3.1.3 实现 τ_tune 动态边剪枝（原 Tune 方法仅单次 GNN forward）

  原代码：加完 prompt 后单次 GNN forward，无中间剪枝。

  修复后（2026-05-21）：两阶段 GNN forward + filter_module 初筛，尝试对齐论文 Equation 15：

    # Stage 0: 添加 multi-prompt + filter_module 初筛
    # Stage 1: 第一次 GNN forward + τ_tune 剪枝
    # Stage 2: 第二次 GNN forward

  ⚠️ 2026-06-03 再次修订（对齐论文原文 Section 4.3）：
  审查论文原文后发现，filter_module（基于原始特征/AX 余弦的边过滤）为代码额外引入，
  论文中不存在此组件。论文的 Filtering Tips（degree/similarity/OOD）全部用于节点分选
  prompt，不用于边剪枝。论文唯一涉及边剪枝的是 τ_tune（Equation 15）。

  最终代码（2026-06-03 对齐论文）：

    # τ_tune 边剪枝（对齐论文 Equation 15）：添加 prompt → GNN forward →
    # 基于中间 embedding 的 cosine similarity 剪枝 → 剪枝后 GNN forward
    g_mutiftpt, node_use_each_pt_whole_graph = self.add_muti_pt(graph, device)

    # 第一次 GNN forward 获取中间 embedding（在全图上，无预剪枝）
    node_emb_intermediate = gnn(g_mutiftpt.x, g_mutiftpt.edge_index)

    # 基于中间 embedding 的 cosine similarity 进行 τ_tune 剪枝
    edge_sim_intermediate = F.cosine_similarity(
        node_emb_intermediate[g_mutiftpt.edge_index[0]],
        node_emb_intermediate[g_mutiftpt.edge_index[1]], dim=1
    )
    tune_keep_mask = edge_sim_intermediate >= self.pt_threshold
    tuned_edge_index = g_mutiftpt.edge_index[:, tune_keep_mask]
    tuned_g = Data(x=g_mutiftpt.x, edge_index=tuned_edge_index, y=g_mutiftpt.y)

    # 第二次 GNN forward 在剪枝后的图上得到最终 node embedding
    node_emb = gnn(tuned_g.x, tuned_g.edge_index)

  MSE loss（L_s, 特征平滑性）基于 τ_tune 剪枝后的图计算：
    loss_mse = F.mse_loss(node_emb[tuned_g.edge_index[0]], node_emb[tuned_g.edge_index[1]])

4.1 Attention 功能是否恢复正常？
--------------------------------------------------------------------------------

  结论：已恢复正常。

  审查要点：

    a) readout token 机制正确
       - 在 K 个 prompt slot 前插入可学习的 readout_token
       - MultiheadAttention 使用 batch_first=True，输入形状 (N, K+1, D)
       - 输出取位置 0（readout token）→ g_mutiftpt_output[:, 0, :]
       - 这是标准的 readout-token 聚合模式（类比 BERT [CLS]）

    b) key_padding_mask 构造正确
       - torch.all(g_mutiftpt_record == padding, dim=-1) → 形状 (N, K+1)
       - True 表示该位置所有特征维度均为零（即空 prompt slot）
       - PyTorch MultiheadAttention 文档：key_padding_mask 为 True 的位置被忽略
       - 符合预期：readout token 只 attend 到非空的 prompt slot

    c) 无防御 prompt 节点的兜底处理
       - node_num_pt = (~key_padding_mask[:, 1:]).sum(-1) 统计非空 slot 数
       - node_num_pt == 0 的节点：没有任何防御 prompt，readout attention 输出无意义
       - 设置为 padding（全零），使 final_x = x + 0 = x，退化为原始特征
       - 这是合理的设计：不需要防御的节点不加 prompt

    d) 与修复前的对比
       - 修复前：attention 输出被 normalize(INPUT) 覆盖 → attention 从未生效
       - 修复后：attention 输出正确保留并作为最终 prompt → attention 真正参与融合

6.1 修订动机
--------------------------------------------------------------------------------

  2026-05-21 的修复引入了 filter_module（基于原始特征/AX 余弦的边过滤）作为 τ_tune
  之前的预剪枝步骤。经重新审读论文原文 (GPromptShield, ICLR 2025)，确认此组件为代码
  额外引入，论文中不存在。具体偏离如下：

  | 组件              | 论文（GPromptShield）          | 2026-05-21 代码       | 偏离性质     |
  |-------------------|-------------------------------|-----------------------|-------------|
  | 边剪枝阶段数       | 1（仅 τ_tune, Eq.15）         | 2（filter_module + τ_tune）| 多余       |
  | filter_module     | 不存在                        | OriginalFilter/NeighborSimilarity/Hybrid | 额外引入 |
  | Filtering Tips    | 节点分选 prompt（sim/deg/OOD） | 同上 + 误用于边剪枝    | 用途混淆    |
  | Eval 时剪枝       | 不做剪枝                      | filter_graph 边过滤    | 多余       |
  | 训练设定           | Inductive（k-hop 子图 batch）  | Transductive（全图）   | 计算效率选择 |

  ★ 关于"训练剪枝、eval 不剪枝"的说明（为什么这不是矛盾）：

  论文 GPromptShield 的防御体系由两部分组成（Section 4）：
    - Direct Handling（MD-PT）：多防御 prompt，在特征空间直接对抗扰动
    - Indirect Amplification（IA-PT）：训练策略层面绕过无效信息、放大有效信息

  τ_tune 剪枝（Eq.15）属于 Indirect Amplification 的训练策略。它是一个训练时正则化
  手段——类似于 Dropout 在训练时随机丢弃神经元但在推理时使用全部神经元。具体而言：

    训练时：GNN₁ forward → 基于中间 embedding 的 cosine similarity 剪掉低相似度边
           → GNN₂ forward 在剪枝后图上计算 loss → 更新 prompt 参数
           目的：防止 prompt 在对抗边上过拟合，迫使 prompt 学习不依赖可疑边的鲁棒表示

    推理时：训练好的 prompt 已经具备鲁棒性，直接 add_muti_pt + GNN forward
           目的：利用全部图结构信息做分类，不做任何边剪枝

  核心直觉：τ_tune 的作用对象是 prompt 参数的学习过程，而非图结构本身。一旦 prompt
  在"干净"的剪枝环境中学会了鲁棒表示，推理时就可以安全地在全图上使用。反之，如果在
  eval 时也做剪枝，反而可能误删正常边，损失有用信息——论文从未在推理阶段做剪枝。

  因此，以下两句话同时为真且互不矛盾：
    (a) 训练时做 τ_tune 边剪枝（对齐论文 Eq.15）
    (b) 推理时不做任何边剪枝（对齐论文 "After the tuning process, during the evaluation
        phase, we add the tuned prompt... obtain the classification result"）

八、2026-06-03 补充：Filtering Tips 分选阈值待调
================================================================================

论文 GPromptShield 的三个 Filtering Tips（Section 4.2）用于节点分选 prompt，各自有阈值参数：

  | 参数名                    | 默认值 | 含义                                           |
  |---------------------------|--------|------------------------------------------------|
  | pt_sim_threshold          | 0.4    | 邻居平均 cosine similarity 阈值，≤此值 → sim_pt |
  | pt_degree_threshold       | 2      | 节点度数阈值，≤此值 → degree_pt                  |
  | pt_out_detect_threshold   | 0.5    | 边 cosine similarity 阈值，≤此值 → out_detect_pt |

这些阈值直接决定每种 defense prompt 覆盖的节点数量和类型。当前使用的是论文建议的默认值，
尚未针对 Cora 数据集调优。Meeting 10 未曾扫过这些参数——这是下一步调参的重点方向。

注意区分：
  - "Filtering Tips 阈值" = 节点分选参数（本节），控制哪些节点获得哪种 defense prompt
  - "filter_module" = 边剪枝模块（本报告 Section 6 移除的），基于特征 cosine 过滤边
  两者是完全不同的概念，不要混淆。
