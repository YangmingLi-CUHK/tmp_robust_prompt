1. 数据分裂 (Split) 全景 — 两套独立体系

项目中存在 两套独立生成的 few-shot split，分别服务于不同数据加载路径：

⚠️ 两套 split 完全不重合：
  • Train 节点交集：0/35 —— 完全不同的 5-shot 抽取
  • Val 节点交集：44/500 (仅 8.8%)
  • Test 节点交集：878/1000 (87.8% 重叠，但有 122 个不同)

这意味着：eval_pretrain.py (Linear Probe 0.626) 和 downstream prompt learning (RobustPrompt-T ~0.44-0.47) 不仅方法不同，评估的测试集也不同。直接比较这两个数字在方法论上不严谨。

攻击数据路径还有 1,173 个节点完全不参与 train/val/test（仅作为 message-passing 基础设施存在），而 data_fewshot 路径覆盖了全部 2,708 个节点。

2. 攻击生成全链路

2.1 生成脚本与参数

入口：generate_few_shot_attack.py

python generate_few_shot_attack.py \
    --dataset Cora --model Meta_Self --ptb_rate 0.05 \
    --shot_num 5 --run_split 1

核心攻击参数：

参数值含义
--modelMeta_Selfλ=0，outer loss 仅在 test nodes 上
surrogateGCN(hidden=16)小容量代理模型，模拟目标 GNN
attack_structureTrue仅攻击图结构（不改特征）
perturbationsint(0.05 × 5278) = 263允许修改的无向边数

2.2 六步攻击链路

1
加载预存 split — 从 data_attack_fewshot/Cora/shot_5/1/index/ 加载 train(35) / val(500) / test(1000) 节点 ID，构建 mask。
2
构建邻接矩阵 — 从 clean edge_index 构建 sp.csr_matrix。原始 Cora: 5,278 条无向边 × 2 = 10,556 entries。
3
训练 Surrogate GCN — 在 clean 图上用 35 个 train labels 训练 hid_dim=16 的小 GCN。这是攻击者的"代理模型"（模拟下游用户会训练的 GNN）。
4
定义攻击目标 — idx_unlabeled = val ∪ test = 1500 nodes。Meta_Self (λ=0) 的 outer loss 完全在这些节点上计算：最大化 GNN 对 test nodes 的预测错误。
5
双层优化攻击 — Metattack 计算 meta-gradient：∂(test loss)/∂(adjacency) through inner training。找出哪些边的增/删能最大程度提升 test loss。
6
保存扰动图 — modified_adj → Meta_Self_Cora_0.05.pt + 对应的 idx_train/val/test.npy。

2.3 Metattack 双层优化公式

Outer Loop（最大化 test loss）：

max_{A'}  L( f_{θ*}(A', X),  Yunlabeled )

Inner Loop（在扰动图上重训 surrogate）：

θ* = argmin_θ  L( f_θ(A', X),  Ytrain )

约束：

||A' - A||₀ ≤ perturbations × 2    (每条无向边 = 2 个稀疏矩阵 entry)

关键：Meta-gradient ∇ALtest 穿过 inner optimization (surrogate 在 train labels 上的训练过程)。这使得攻击可以预判"如果我在某处加一条边，surrogate 重训后会如何错误分类 test nodes"。

由于 λ=0 (Meta_Self)，outer loss 完全不考虑 train nodes 的预测质量。攻击的唯一目标是让 test nodes 被分错——这给了 Metattack 最大的自由度去植入 train↔test 假边。

4. 数据泄露 (Data Leakage) 深度分析

🔴 核心问题：在 transductive setting 下，攻击者拥有"明牌"优势。

4.1 攻击者知道什么？

信息攻击者是否已知来源
全图结构 (edge_index)✓ 已知公开数据集
所有节点特征 (X)✓ 已知公开数据集
Train 节点 ID (35 nodes)✓ 已知攻击脚本显式加载 split 文件
Val 节点 ID (500 nodes)✓ 已知同上
Test 节点 ID (1000 nodes)✓ 已知同上
Test 节点标签✗ 未知攻击 loss 不直接使用标签，而是最大化预测不确定性
下游使用的 GNN 架构~ 近似已知用 surrogate GCN 近似（可迁移到其他架构）
预训练 backbone 权重✗ 未知攻击基于随机初始化 surrogate，非预训练模型

4.2 为什么这是 "数据泄露"？

在实际部署中，攻击者不应该知道哪些节点会被用于测试。然而在当前 transductive pipeline 中：

  1. Split 在攻击前就已固定 — data_attack_fewshot/Cora/shot_5/1/index/ 在攻击生成时被显式读取
  2. 攻击者看到 train/val/test 的完整划分 — 75.9% 的新增边精准瞄准 train↔test 对
  3. 攻击不需要猜测 — Metattack 的 meta-gradient 直接计算 ∂(test node loss)/∂(edge)，它是"开卷考试"
  4. 每 train node 平均被植入 6.6 条假边连接 test nodes (ptb=0.05) 到 27.9 条 (ptb=0.25)

4.3 攻击对 Message Passing 的污染机制

2 层 GCN 中，每个 test node 聚合其 2-hop 邻居信息：

GCN Layer 1:  hᵥ⁽¹⁾ = σ( Σ_{u∈N(v)} W⁽¹⁾ hᵤ⁽⁰⁾ )
GCN Layer 2:  hᵥ⁽²⁾ = σ( Σ_{u∈N(v)} W⁽²⁾ hᵤ⁽¹⁾ )

假边效果：
  Layer 1: test node ← 聚合了 fake train neighbor 的特征
  Layer 2: test node ← 通过 fake neighbor 间接聚合了更多错误信息

一条 train↔test 假边的影响范围：

  • 1-hop: 直接连接的 test node 被污染
  • 2-hop: 该 test node 的邻居也通过聚合被间接污染
  • train node 侧: train node 的 embedding 也因多了 fake neighbor 而偏斜 → 影响下游分类头的训练
🔴 直接污染 (1-hop)

假边两端的 test node 直接从不同类的 train node 接收错误信息。这是最主要的攻击效果——GNN 的同质性归纳偏置被系统性地利用。

🟠 级联污染 (2-hop+)

被污染的 test node 继续向其邻居传播错误 embedding。随着 GNN 层数增加，一圈污染扩散为一片。2 层 GCN 下影响半径 = 2 hops。

5. Transductive vs Inductive — 为什么论文用 Subgraph

维度Transductive (当前)Inductive (论文)
图结构 单张全图，train+test 节点共存 每个节点提取 k-hop 子图为独立 sample
Message Passing train↔test 直接通信 子图间隔离，test node 不与 train node 同图
攻击难度 低 — 攻击者知道 test nodes 身份 高 — 攻击者不知哪些子图是 test
train↔test 假边效果 直接污染 无法植入（不在同一子图）
污染浓度敏感性 极高 — 0.05 已致命 相对稀释 — 子图化自然减毒

这解释了 CLAUDE.md 中记录的 Transductive vs Inductive gap：在 transductive 下，230 条精心瞄准的 train↔test 假边足以在 0.05 浓度下造成严重破坏（GPPT 0.435→0.279，RobustPrompt-T 0.44→0.24）。而在 inductive 子图设定中，攻击只能扰动子图内部，train↔test 边无法存在。

6. 发现的问题汇总与建议

6.1 🔴 严重问题

#问题影响
1 两套 Split 不统一 — data_fewshot ≠ data_attack_fewshot eval_pretrain 和 downstream 实验测的是不同测试集，不可直接比较
2 攻击者知道完整 split — 75.9% 假边精准打 train↔test Transductive 设定下攻击效果被放大，低估了实际鲁棒性
3 eval_pretrain 从未在被攻击图上评估 — 只测了 clean 不知道 Linear Probe 在攻击下的真实表现。如果 LR 在攻击下暴跌，那就不是方法差异而是 embedding 被破坏

6.2 🟡 改进方向

#建议优先级
1 统一 Split — 所有实验用同一套 data_fewshot 索引。需重新生成攻击数据（使用 data_fewshot 的 split 作为攻击输入） 高
2 补做 eval_pretrain 在攻击图上的测试 — 直接回答"Linear Probe 在攻击下垮不垮" 高
3 跑 Inductive (RobustPrompt-I) 实验 — 子图化天然防御 transductive 攻击 中
4 考虑 Blind Attack 设定 — 攻击者不知道 split，只能随机扰动。对比 White-box (当前) vs Grey-box vs Blind 的表现差距 低

6.3 立即可做的快速验证

用 eval_pretrain.py 在攻击图上跑一轮：

# 修改 eval_pretrain.py 使其加载攻击图而非 clean 图
