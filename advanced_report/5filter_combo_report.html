Analysis & Key Findings

1. Fix verified — focusedcleaner_pt now properly disabled. With the task.py fix (threshold < 0 → key removed from pt_dict), all 31 combos × 6 ptb now correctly isolate individual filter contributions. This corrected data serves as the p_plus=True baseline for this report.
2. p_plus ablation — overall effect is small but consistently negative on clean data. Across all shared combos, p_plus=False reduces clean accuracy by -0.2124 on average (NSP true-label) and -0.0796 (NSP-IA). At M-0.25, the delta is +0.0240 (NSP) and -0.1376 (NSP-IA). This confirms that the 20-token bank (p_plus=True, ~10K params/filter) provides modest but consistent gains over single-token prompts (~256 params/filter) — the extra capacity helps, but not dramatically. The average rank shift between p_plus=True vs False is 9.8 positions — combo ordering is largely preserved.
3. NSP true-label: accuracy collapses under attack regardless of p_plus. p_plus=True: best clean = 0.5983 → best M-0.25 = 0.1155 (drop = 0.483). p_plus=False: best clean = 0.4371 → best M-0.25 = 0.1821 (drop = 0.255). Under M-0.25, the best any combo achieves is ~0.1155 — barely above random (1/7 ≈ 0.143). The p_plus parameter does not rescue robustness.
4. NSP-IA: near-flat accuracy across ptb — confirms test leakage (unchanged). p_plus=True: best clean = 0.5820 → best M-0.25 = 0.5606 (drop = 0.021). p_plus=False: best clean = 0.4841 → best M-0.25 = 0.4374 (drop = 0.047). The IA pseudo-label expansion (35→~595 from test set) creates apparent robustness via transduction leakage. p_plus=False makes IA clean accuracy slightly worse — the pseudo-label noise hurts more when prompt capacity is reduced.
5. p_plus=False changes best combo at clean but not at M-0.25. NSP clean best: p_plus=True → deg+ood+nsp+fc (0.5983), p_plus=False → deg+ood+nsp+fc (0.4371). NSP M-0.25 best: p_plus=True → fc (0.1155), p_plus=False → nsp+fc (0.1821).
6. sim_pt is unstable in both p_plus modes. p_plus=True: sim has 0 ptb levels with 0/5 valid seeds. p_plus=False: 0 NaN levels. The instability persists regardless of token capacity — it is a fundamental issue with the cosine-similarity detection threshold, not a parameterization problem.
7. Single-filter ranking is consistent across p_plus modes. p_plus=True: ood=0.5901 > nsp=0.5822 > degree=0.5775 > fc=0.5702 > sim=0.5208 p_plus=False: sim=0.4195 > fc=0.3921 > ood=0.3810 > degree=0.3621 > nsp=0.2990 Both modes agree that ood is the best single filter on clean data. The order of the 5 single filters is largely preserved, confirming the relative filter quality is a property of the detection method, not the prompt token capacity.
8. nsp_pt and focusedcleaner_pt remain competitive new additions. Both new filters hold their own across p_plus modes: nsp: 0.5822 (pp=True) vs 0.2990 (pp=False); fc: 0.5702 (pp=True) vs 0.3921 (pp=False); degree: 0.5775 (pp=True) vs 0.3621 (pp=False). At M-0.25, fc is the best single filter in both modes: 0.1155 (pp=True) / 0.1078 (pp=False).
9. IA-nopplus 4/5-combo data incomplete — excluded from analysis. The NSP-IA + p_plus=False experiments for 4-filter and 5-filter combos had incomplete seed data (0-3 valid seeds out of 5 at most ptb levels). These are excluded from all tabs and analysis.
