3. p_plus Token Bank: 231K 参数 / 35 标签

3.1 参数量分析

p_plus=True: 4 × (20×1433 token bank + Linear(1433,20)) = 229,360 参数
Readout token: 1,433
Classifier: Linear(64, 7) = 455
─────────────────────────
TOTAL: 231,248 参数 / 35 标签 = 6,607 参数/标签
p_plus=False: 4 × 1,433 + 1,433 + 455 = 7,620 参数 / 35 标签 = 218 参数/标签
p_plus 的 Linear(1433,20) 每个有 28,680 个权重，用 35 个标签根本无法学到有意义的东西。 Token bank 权重基本是随机初始化。但 20 个 1433-dim dense token 仍然强力覆盖了 ~19 个非零值的稀疏 BoW 特征。

4. 输入空间污染：Dense Prompt 淹没 Sparse BoW

Cora BoW 特征Prompt Token
维度14331433
非零值~19 (1.3%)1433 (100%)
L0 范数比1×~77×
GNN 输入 = xBoW (19 non-zeros) + pdense (1433 non-zeros)
→ GNN 看到的几乎全是 prompt，不是论文内容
→ GNN 是在 BoW 上预训练的，冻结后面对 BoW+dense_prompt 分布偏移 → 第一层 GCNConv 产出垃圾
Prompt 设计在特征空间（1433-dim），而不是 embedding 空间（64-dim）。 在特征空间加 prompt 等价于改写整篇论文的词频向量——对每个词都加一个偏移——而不是在语义层面调整表示。 如果在 GNN 的输出端（64-dim）加 prompt，线性探测已经证明这个空间是线性可分的，小偏移不会破坏它。

6. KL Loss 反噬 (weight=0.3, 3× MSE)

KL(prompt_node_embedding || no_prompt_node_embedding) weight=0.3
→ 把带 defense prompt 的节点 embedding 拉向不带 defense prompt 的节点
→ 但"不带 defense prompt"只有 p_e only 那 850 个节点
→ 其余 1858 个带 defense prompt 的节点被强行拉向它们
→ defense 效果被 KL loss 抵消
KL loss 的设计意图是"让 biased 节点分布对齐 unbiased 节点"，但实际上变成了让所有带 defense prompt 的节点退化为不带 defense prompt 的节点——等于关掉了 defense。

8. 综合判断

论文 Table 1 的 Cora + GraphCL 列（MD-PT: Clean 49.39/M-0.25 48.06, IA-PT: Clean 57.82/M-0.25 58.82）无法通过复现验证。

五个独立的结构性缺陷共同导致了这个结果：
1. IA-PT 使用了 560 个测试集伪标签（训练集从 35→595），论文未强调此差异
2. p_plus token bank (231K params) 在 35 标签下无法学习，但 dense prompt 仍淹没稀疏 BoW
3. 特征空间 prompt（1433-dim dense）被冻结 GNN 视为分布偏移，而非增强
4. KL loss (weight=0.3) 主动抵消了 defense prompt 的效果
5. 仅有 4 种 prompt 组合覆盖 2708 个节点，退化为 group embedding

即使论文的 MD-PT 行（35 标签）claim 的 48% M-0.25 也与我们的 ~10% 差距过大（38pp），无法用调参或 backbone 质量解释。该行数据的可信度存疑。
